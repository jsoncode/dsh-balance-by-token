# DSH 余额插件（dsh-balance-by-token）开发计划

## 调研结论（已验证的关键机制）

- **插件形态**：双面插件，完全复刻 `D:\code\owner\dsh-jenkins` 的工程结构（host ESM + client CJS `__ModuleLoader__` 工厂、`dsh.bundle`/`dsh.client` manifest、`cordis.patch.yml`、pnpm + tsdown + tsc -b）。
- **API Key 来源**：宿主 `settings.get('llm-pi-ai')` 得到 `providers: { <route>: { baseURL, apiKeyEnv } }`；另有 `settings.get('llm-deepseek')`（route `deepseek-official`，默认 `apiKeyEnv: DEEPSEEK_API_KEY`）。过滤 `baseURL` 含 `deepseek`（或 deepseek 官方路由）的条目，经 `ctx.get('credentials').resolve(apiKeyEnv)` 取真实 key，调用官方接口 `GET https://api.deepseek.com/user/balance`（`Authorization: Bearer <key>`，返回 `balance_infos[].total_balance/granted_balance/currency`）。
- **Token 用量**：session 事件的 `assistant/message` 携带 `usage { inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens }`，事件信封含 `time`（epoch ms）；`request/context` 事件记录 `{ provider, model }`。官方 `tokenUsage` 投影即按 step 去重累加这四个桶——费用计算在宿主侧复刻同样逻辑（按 turn/step 后值覆盖前值，以 `assistant/message` 为准）。
- **今日聚合**：session 日志位于 `dshHomePath('sessions')/<projectKey(cwd)>/<sessionId>/session.jsonl(.zstd)`（默认 zstd 压缩，`node:zlib` 的 `zstdDecompressSync` 可解）。首行为 header（含 `cwd`/`createdAt`），后续行 `{ type, seq, time, data }`。按文件 mtime >= 当日零点粗筛，再按事件 `time` 精滤。
- **当前会话**：客户端经 slot props `useSessions(s => s.current)` 取 sessionId 随 RPC 上传；宿主 `ctx.get('sessions').get(id)` 取内存 Session（含全量 events）。「最近一次提问」= 最后一个 turn 的所有 step usage 之和；「本会话」= 全量之和。
- **宿主无内置计费**：`llm-pi-ai/catalog.ts` 明确 "harness never reads pi-ai's cost metadata"，价格表完全由本插件自管（settings namespace 持久化，弹框内可编辑）。
- **通信**：复刻 dsh-jenkins 的 `webServer.register({ kind:'exact', path:'/dsh-balance/api' })` + 信任围栏（复用其 `fence.ts` 逻辑），客户端 fetch POST JSON；保留 commands 通道兜底。

## 宿主半边（src/host/）

- `index.ts`：`inject = ['shell','settings','credentials','commands']`；注册 settings namespace `dsh-balance`（字段：`extraKeysJson` 手动附加的 API key 列表、`pricesJson` 价格配置、均以 JSON 字符串存储规避数组冻结）；注册 `/dsh-balance/api` HTTP 路由与 `dsh-balance` 兼容命令，分发到 `ops.ts`。
- `providers.ts`：枚举 DeepSeek 服务商——合并 `llm-pi-ai.providers`（baseURL 含 deepseek 者）、`llm-deepseek` 官方路由、插件自有 `extraKeys`；每项输出 `{ id, label, baseUrl, apiKeyMasked, source }`。
- `balance.ts`：对每个服务商并行请求官方余额接口（fetch + Bearer，10s 超时），聚合 `{ ok, total_balance, granted_balance, currency, topped_out }` 或错误文案；结果内存缓存 60s（手动刷新绕过）。
- `cost.ts`：
  - `turnCost(session)` / `sessionCost(session)`：遍历内存 events，按 `tokenUsage` 投影逻辑折叠四桶；按 model（最近 `request/context`）匹配价格表计费。
  - `todayCosts(currentCwd)`：扫描 `dshHomePath('sessions')` 下 mtime>=今日零点 的日志 → `zlib.zstdDecompressSync`/明文读取 → 逐行 JSON.parse，只取 `assistant/message`（usage）与 `request/context`（model），按 `time >= 今日零点` 过滤；按 header `cwd` 区分「本项目/全部」；当日结果按 (文件路径+mtime) 记忆化缓存，避免重复全量扫描。
  - 计费公式：`(uncachedInput*pUncached + cacheRead*pCacheRead + cacheWrite*pCacheWrite + output*pOutput) / 1e6`（每百万 tokens 单价）。
- `types.ts`：OpRequest/OpResult、价格档位类型。

**价格配置模型**（`pricesJson`）：一组可编辑的价格档位，每档 `{ id, name, currency: 'CNY', match: 模型匹配串, input, cacheRead, cacheWrite, output }`；默认内置 DeepSeek 官方档位（deepseek-chat / deepseek-reasoner / 通配 `*` 兜底，数值为官方每百万 tokens 价格，用户可改）。匹配优先级：精确 model id > 前缀 > 通配兜底。

**Ops 列表**：`providers`（列服务商）、`balance`（查余额）、`cost { sessionId }`（四项费用）、`pricesGet` / `pricesSave`、`keysGet` / `keysSave`（手动附加 key）。

## 浏览器半边（src/client/）

- `index.ts` + `plugin.tsx`：`inject: ['slots','remote','remote.commands','timer']`；
  - `sidebar.footer.action` 注册「余额」按钮（`FooterButton`，复刻 jenkins 的 order 动态计算，默认靠后），点击打开统一弹框；
  - `shell.overlay` 注册 `dsh-balance-modal`（order 100）——**所有余额设置与显示统一在此弹框**。
- `components/BalanceModal.tsx`：三 Tab 弹框：
  1. **余额**：服务商列表（来源标签、脱敏 key、`total_balance`/`granted_balance` 展示），每行独立状态（成功/失败原因），顶部「全部刷新」；底部入口「附加 API Key」（手动添加不在 providers 配置中的 key，脱敏展示、可删除）。
  2. **费用**：四卡片——最近一次提问 / 本会话 / 今日·本项目 / 今日·全部，各卡片展示金额 + token 明细（输入(缓存未命中)/缓存命中/缓存写入/输出），底部显示当前生效价格档摘要与「刷新」。
  3. **价格设置**：档位列表（名称、模型匹配、四项单价、货币），行内编辑 + 增删 + 「恢复官方默认」，保存走 `pricesSave`。
- `rpc.ts`：复刻 jenkins 的 HTTP 优先 + 命令通道兜底（路由 `/dsh-balance/api`）。
- `store.ts`：弹框开关 store（同 jenkins `makeConfigModalStore`）。
- `i18n.ts`：中英双语文案；`styles.ts`：弹框/卡片/表格样式（沿用 jenkins 的设计语言与 CSS 变量）。

## 测试计划

1. `npm run check && npm run build && npm run verify` 通过。
2. 本地 `dsh plugin --profile web add ./dsh-balance-by-token` 安装，web 端验证：footer「余额」按钮出现 → 弹框三 Tab 正常 → 余额查询（真实 key 或观察 401 文案）→ 发一轮对话后四项费用非零且随对话增长 → 修改价格后费用按新单价变化 → 附加 key 增删持久化（重启后回显）。
3. 边界：无 DeepSeek 服务商时余额 Tab 空态提示；无凭据时显示「未配置凭据」；zstd 与明文日志均可解析。

## 假设与决策

- 余额查询走宿主代理（凭据在宿主，且规避浏览器 CORS）。
- 「今日」聚合采用按需扫描 + mtime 粗筛 + 事件 time 精滤 + 记忆化缓存（无需后台账本，天然覆盖插件安装前的历史）。
- 费用只统计 `assistant/message` 的最终 usage（与官方投影一致；被压缩替换的历史节点不计二次费）。
- 单价单位为「每百万 tokens」，货币默认 CNY，可编辑。
